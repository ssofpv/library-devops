## Текущее состояние

Создан каркас приложения на Django и Django REST Framework.

Реализован служебный адрес GET /health/.
Он проверяет, что приложение отвечает на HTTP-запросы.
Доступность базы данных этот адрес не проверяет.

API авторов реализован, а API книг ещё предстоит сделать.

Добавлены два автоматических теста:
- успешный GET-запрос к /health/;
- запрет POST-запроса к /health/.

В модуле catalog реализованы модели Author и Book, связь многие ко многим и начальная миграция.

Добавлены три теста хранения данных и связей каталога. Всего в проекте 13 тестов.

HTTP API каталога, ограничения удаления и модуль библиотечного фонда ещё предстоит реализовать.

Сейчас используется стандартная настройка SQLite.
Настроены команды Make и автоматические проверки GitHub Actions.
В CI проект проверяется на Python 3.13 и 3.14.

## Локальный запуск в Windows PowerShell

Все команды выполняются из основной папки репозитория,
в которой находится manage.py.

### 1. Создание виртуального окружения

```powershell
py -m venv .venv
```

Если окружение .venv уже создано, повторять этот шаг не нужно.

### 2. Установка зависимостей

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 3. Настройка окружения

Если файла .env ещё нет, создайте его из образца:

```powershell
Copy-Item .env.example .env
```

Сгенерируйте собственный секретный ключ:

```powershell
.\.venv\Scripts\python.exe -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

Откройте .env и вставьте полученное значение после DJANGO_SECRET_KEY=.
Не публикуйте ключ и не добавляйте .env в Git.

### 4. Подготовка стандартных таблиц базы данных

```powershell
.\.venv\Scripts\python.exe manage.py migrate
```

Команда создаёт стандартные таблицы Django в локальной SQLite-базе.
Модели авторов, книг, филиалов и экземпляров пока не добавлены.

### 5. Проверка конфигурации

```powershell
.\.venv\Scripts\python.exe manage.py check
```

### 6. Запуск сервера

```powershell
.\.venv\Scripts\python.exe manage.py runserver
```

Откройте http://127.0.0.1:8000/health/

Ожидаемый ответ:

```json
{"status": "ok"}
```

Главная страница по адресу / пока не реализована и возвращает 404.

Для остановки сервера нажмите Ctrl+C в терминале.

## Автоматические тесты

```powershell
.\.venv\Scripts\python.exe manage.py test config
```

Ожидаемый результат: два теста завершились успешно, в конце вывода — OK.

## Единые команды проекта

Для выполнения команд нужен GNU Make версии 3.82 или новее.

В Windows его можно установить через WinGet:

```powershell
winget install --id ezwinports.make --exact --source winget
```

После установки необходимо перезапустить редактор и терминал.

Перед использованием команд:
- создайте виртуальное окружение .venv;
- подготовьте локальный .env по инструкции выше.

Установка зависимостей приложения и инструментов разработки:

```powershell
make setup
```

Основные команды:

| Команда | Назначение |
|---|---|
| make run | Запуск приложения |
| make migrate | Применение миграций |
| make test | Запуск всех тестов |
| make quality | Анализ кода и проверка форматирования |
| make format | Исправление порядка импортов и форматирования |
| make verify | Полный набор обязательных проверок |

Перед отправкой изменений необходимо выполнить make verify.

## Автоматические проверки

GitHub Actions запускает make verify при отправке коммитов
и при создании или обновлении Pull Request.

Проверки выполняются на Python 3.13 и 3.14.

Конфигурация: .github/workflows/ci.yml.
