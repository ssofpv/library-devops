# library-devops

Учебный проект «Библиотека» по дисциплине
«Методология и практики DevOps».

Приложение предоставляет HTTP API для работы с авторами, книгами,
филиалами и физическими экземплярами книг.

## Возможности

- Создание, просмотр, изменение и удаление авторов и книг.
- Связь многие ко многим между книгами и авторами.
- Создание, просмотр, изменение и удаление филиалов и экземпляров.
- Перемещение экземпляров между филиалами.
- Фильтрация экземпляров по книге и филиалу.
- Проверка обязательных полей и уникальности инвентарного номера.
- Запрет удаления автора, связанного с книгами, через API.
- Защита книги и филиала от удаления при наличии экземпляров.

Данные хранятся в локальной базе SQLite.

Авторизация пока не настроена.
Приложение предназначено для локальной учебной работы.
Отдельный пользовательский интерфейс не реализован;
для ручной работы доступен браузерный интерфейс Django REST Framework.

## Требования

- Git и доступ к закрытому репозиторию.
- Python 3.13 или 3.14.
- PowerShell для приведённых ниже команд Windows.
- GNU Make для единых команд проекта.

В GitHub Actions проверки выполняются на Python 3.13 и 3.14.

## Установка в Windows PowerShell

### 1. Получение проекта

Выполните в папке, где будет размещён проект:

```powershell
git clone https://github.com/ssofpv/library-devops.git
cd library-devops
```

Репозиторий закрытый: при необходимости авторизуйтесь
через предложенный Git способ входа в GitHub.

Остальные команды выполняются из папки с manage.py.

### 2. Создание виртуального окружения

Для Python 3.14:

```powershell
py -3.14 -m venv .venv
```

Если установлен Python 3.13, используйте:

```powershell
py -3.13 -m venv .venv
```

Выполните только одну из этих команд.
Если .venv уже создана для проекта, повторять шаг не нужно.

Активация окружения не обязательна:
команды ниже явно используют Python из .venv.

### 3. Установка зависимостей

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

Будут установлены зависимости приложения из requirements.txt
и инструменты разработки, включая Ruff.

### 4. Настройка переменных окружения

Если .env ещё нет, создайте его:

```powershell
Copy-Item .env.example .env
```

Сгенерируйте секретный ключ:

```powershell
.\.venv\Scripts\python.exe -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

Откройте .env и замените значение DJANGO_SECRET_KEY
на полученный ключ. Заключите ключ в двойные кавычки:

```dotenv
DJANGO_SECRET_KEY="сюда-вставить-сгенерированный-ключ"
DJANGO_DEBUG=true
DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1
```

Не публикуйте ключ. Файлы .env, db.sqlite3 и папка .venv
не должны попадать в Git.

### 5. Создание таблиц базы данных

```powershell
.\.venv\Scripts\python.exe manage.py migrate
```

Команда создаёт стандартные таблицы Django и таблицы приложения:
авторов, книг, их связей, филиалов и экземпляров.

Новая база изначально не содержит библиотечных записей.
Данные из базы другого участника через Git не передаются.

### 6. Проверка проекта

```powershell
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.\.venv\Scripts\python.exe manage.py test
```

Все команды должны завершиться успешно.
Проверка миграций должна сообщить No changes detected,
а тесты — завершиться с OK.

При установленном GNU Make весь набор проверок запускается
одной командой:

```powershell
make verify
```

### 7. Запуск сервера

```powershell
.\.venv\Scripts\python.exe manage.py runserver
```

Оставьте терминал работающим и откройте браузер.

| Адрес | Назначение |
|---|---|
| http://127.0.0.1:8000/health/ | Проверка работоспособности |
| http://127.0.0.1:8000/api/authors/ | Авторы |
| http://127.0.0.1:8000/api/books/ | Книги |
| http://127.0.0.1:8000/api/branches/ | Филиалы |
| http://127.0.0.1:8000/api/copies/ | Экземпляры |

GET /health/ возвращает:

```json
{"status": "ok"}
```

Этот адрес проверяет ответ приложения, но не доступность базы данных.

Главная страница / не реализована и возвращает 404.

Для остановки сервера нажмите Ctrl+C.
При следующем запуске достаточно снова выполнить runserver;
повторная установка зависимостей не нужна.
После получения новых миграций из Git необходимо выполнить migrate.

## Единые команды проекта

Для установки GNU Make в Windows:

```powershell
winget install --id ezwinports.make --exact --source winget
```

После установки перезапустите терминал и при необходимости VS Code.

Команды выполняются из папки проекта после создания .venv.
Для запуска приложения и проверок подготовьте .env.

| Команда | Назначение |
|---|---|
| make setup | Установка зависимостей приложения и разработки |
| make run | Запуск сервера |
| make migrate | Применение миграций |
| make test | Запуск всех тестов |
| make quality | Анализ кода и проверка форматирования |
| make format | Исправление порядка импортов и форматирования |
| make verify | Полный набор обязательных проверок |

## Совместная разработка

Изменения выполняются через Issues, отдельные ветки и Pull Request.
Перед отправкой изменений необходимо выполнить make verify.
Перед слиянием нужны успешные проверки CI и одобрение второго участника.

GitHub Actions запускает проверки при отправке изменений
и при создании или обновлении Pull Request.

Конфигурация: .github/workflows/ci.yml.
