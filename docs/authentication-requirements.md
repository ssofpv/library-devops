# Дополнение к ТЗ от 18 сентября 2026 года

Основание — новое обязательное требование ЛР1 об аутентификации.
Дополнение подготовлено для согласования с преподавателем вместе с обновлённым ТЗ.

## Изменение границ версии

В первую версию включаются вход сотрудника по логину и паролю и выход.
Разделение сотрудников по ролям и публичная самостоятельная регистрация не входят
в минимальный объём. Каждый активный пользователь имеет доступ к общему каталогу.

## FR-10 Аутентификация

- Администратор создаёт учётные записи; готовых паролей в исходном коде нет.
- Успешный вход создаёт сессию; неверный пароль и неактивная запись вход не разрешают.
- Все рабочие HTML-страницы и операции API требуют действующей сессии.
- Без входа HTML перенаправляет на форму входа, API возвращает 403.
- POST выхода завершает сессию; GET выхода не изменяет состояние и возвращает 405.
- Пароли хранятся как хеши Django. Формы входа, выхода и изменяющие запросы
  с сессией защищены CSRF. Внешний next не допускается.
- GET /health/ остаётся общедоступным.

## AC-10 Приёмка аутентификации

Проверить успешный и неуспешный вход, запрет доступа без сессии ко всем четырём
сущностям в HTML/API, выход и повторный запрет доступа, неизменность данных при
отказе, доступность health, CSRF и работу обычного пользователя без прав администратора.
Критерии AC-01–AC-06 выполняются после входа. AC-07 проверяется также без входа.
Приёмка требует AC-01–AC-10; GitHub PR, review и CI проверяются отдельно.
