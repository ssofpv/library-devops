# Наблюдаемость library-lab

Приложение пишет JSON-журнал запросов в stdout. В записи есть время UTC,
уровень, тип события, шаблон маршрута, HTTP-статус и идентификатор. Заголовок
ответа `X-Request-ID` позволяет найти соответствующую запись.

Prometheus опрашивает Django и Node Exporter каждые 15 секунд. Панель
Grafana «Библиотека — library-lab» содержит доступность приложения и БД,
запросы, ошибки 5xx, p95 времени ответа, CPU, RAM и диск ВМ, а также количество
доступных экземпляров. Графики нагрузки и p95 исключают служебный `/health/`.
При недоступной БД число экземпляров отсутствует, а `library_app_ready` равно нулю.
Правило `LibraryUnavailable` переходит в Firing, если сбой наблюдается 30 секунд.
Его состояние смотрят на странице Alerts в Prometheus.

## Доступ

Порты Prometheus и Grafana слушают только loopback на `library-lab`.
С Windows открой SSH-туннель под `sofia` на актуальный Host-only IP ВМ.

```powershell
ssh -i "$env:USERPROFILE\.ssh\library_sofia" -o IdentitiesOnly=yes -N -L 13000:127.0.0.1:3000 -L 19090:127.0.0.1:9090 sofia@192.168.56.105
```

Адрес в команде — последний известный. Grafana открывается по
`http://127.0.0.1:13000/d/library-observability`, Prometheus по
`http://127.0.0.1:19090/targets`. Для первого входа в Grafana логин `admin`.
Пароль создаётся при первом развёртывании и хранится на контроллере рядом
с Vault в `~/.config/library-lab/grafana-admin-password`. Используй его
только в окне входа и исключи из доказательств для отчёта.

## Диагностика и восстановление

На `library-lab` из `/opt/library-lab` проверь состояние сервисов и
последние журналы. Сопоставь время наблюдения на панели с журналами.

```sh
cd /opt/library-lab
sudo docker compose --project-name library-lab ps -a
sudo docker compose --project-name library-lab logs --since 10m --tail 100 app db
```

Если Prometheus показывает успешный опрос, но `library_app_ready=0` и
`/health/` возвращает 503, проверь состояние и журналы PostgreSQL.
Если выяснилось, что остановлен сервис `db`, запусти существующий контейнер:

```sh
sudo docker compose --project-name library-lab up -d --wait db
```

Проверь, что с Windows `/health/` снова возвращает 200, текущий `/version/`
соответствует ожидаемому SHA, `library_app_ready=1` и оповещение погасло.
Затем проверь страницу каталога в браузере. Если причина в новом образе,
примени с контроллера `deploy-lab.sh <предыдущий_подтверждённый_SHA>`
после проверки совместимости схемы. Состояние и данные БД проверяются
отдельно. При диагностике сохраняй только нужные строки, убирая секреты
и другие чувствительные данные.
