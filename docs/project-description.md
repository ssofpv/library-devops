Лабораторная работа № 1 по дисциплине «Методология и практики DevOps».

- Скрынникова П. А.

## 1. Назначение приложения

Приложение «Библиотека» предназначено для ведения каталога книг
и учёта физических экземпляров в филиалах библиотеки.

Основной пользователь — сотрудник библиотеки. Он сможет добавлять,
просматривать и изменять сведения об авторах, книгах, филиалах
и экземплярах, а также удалять записи с учётом установленных ограничений.

Первая версия приложения предоставляет HTTP API.
Данные хранятся в реляционной базе данных и сохраняются
после перезапуска приложения.

Этот документ описывает планируемую первую версию приложения.

## 2. Основные сущности

| Сущность | Назначение | Основные поля |
|---|---|---|
| Автор | Сведения об авторе произведений | Уникальный идентификатор, имя автора |
| Книга | Запись об определённом издании книги | Уникальный идентификатор, название, год издания |
| Филиал | Подразделение библиотеки, в котором находятся экземпляры | Уникальный идентификатор, название, адрес |
| Экземпляр | Одна физическая книга | Уникальный идентификатор, уникальный инвентарный номер, ссылка на книгу, ссылка на филиал |

Связи книг и авторов хранятся в промежуточной таблице.
Каждая запись этой таблицы содержит идентификатор книги
и идентификатор автора. Одна и та же пара не должна повторяться.

Книга и экземпляр — разные сущности.
Если библиотека располагает тремя экземплярами одного издания,
в системе создаётся одна запись книги и три записи экземпляров.

### Уточнения модели каталога

- Имя автора обязательно, максимальная длина — 200 символов.
- Название книги обязательно, максимальная длина — 300 символов.
- Год издания необязателен. При валидации указанное значение
  должно быть не меньше 1.
- Книгу разрешено зарегистрировать без указания авторов,
  если сведения о них пока неизвестны.
- Связь книг и авторов хранится в промежуточной таблице.
  Повторная связь одной книги с одним автором не создаётся.

## 3. Связи между сущностями

- Один автор может быть связан с несколькими книгами.
- Одна книга может быть связана с несколькими авторами.
- Одна книга может иметь несколько экземпляров.
- Каждый экземпляр относится к одной книге.
- В одном филиале может находиться несколько экземпляров.
- Каждый экземпляр относится к одному филиалу.

## 4. Функции первой версии

1. Добавление, просмотр и изменение авторов.
2. Добавление, просмотр и изменение книг.
3. Установление связей между книгами и авторами.
4. Добавление, просмотр и изменение филиалов.
5. Регистрация и просмотр экземпляров.
6. Изменение филиала, к которому относится экземпляр.
7. Получение списка экземпляров выбранной книги.
8. Получение списка экземпляров выбранного филиала.
9. Удаление записей при соблюдении установленных ограничений.
10. Обработка некорректных запросов с понятным сообщением об ошибке.

Учёт читателей, выдач, возвратов, штрафов, бронирований и факультетов,
а также формирование отчётов не входят в первую версию.
Они могут быть добавлены при дальнейшем развитии проекта.

## 5. Основные правила

1. Инвентарный номер экземпляра уникален во всей системе.
2. Экземпляр можно зарегистрировать только для существующей книги
   и существующего филиала.
3. Нельзя удалить филиал, пока к нему относятся экземпляры.
4. Нельзя удалить книгу, пока у неё существуют экземпляры.
5. Нельзя удалить автора, пока он связан с книгами.
6. Обязательные текстовые поля не могут быть пустыми
   или состоять только из пробелов.
7. Отклонённая операция не должна приводить к потере
   или непредусмотренному изменению данных.

Основное правило предметной области:
нельзя удалить филиал, в котором зарегистрированы экземпляры книг.

## 6. Основной сценарий использования

1. Сотрудник добавляет автора.
2. Создаёт книгу и связывает её с автором.
3. Добавляет филиал библиотеки.
4. Регистрирует экземпляр книги, указывая инвентарный номер и филиал.
5. Получает список экземпляров выбранного филиала.
6. При необходимости изменяет филиал экземпляра.
7. При попытке удалить непустой филиал получает сообщение
   о запрете операции. Филиал и экземпляры остаются в базе.
